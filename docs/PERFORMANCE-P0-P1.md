## Diagnosis
CPU submission and biological simulation not primary measured cost: living animated simulation .49 ms mean, unified animated .79 ms. GPU living color dominates measured passes (15.96 ms alone, vs .90 ms ROI mask); disabling motion barely changes color cost (15.95 ms), FPS (13.31 vs 13.35) or unified GPU cost (22.57 vs 22.96). Mask removal alone is not sufficient. P1 unified has 64 draw calls including fish; previous living count ~28 excludes fish, not comparable. GPU timers are asynchronous, sampled subsets, not additive wall times; original/static color and Canvas2D/browser compositor are not timed by GPU query. The ~75–82 ms RAF interval is much larger than measured CPU and WebGL durations. Pixel fill/overdraw, full-size Canvas2D blending and compositor/memory bandwidth are leading hypotheses, not proven causal attribution. No timer disjoint events. No claim a library swap solves this.
## P1.1 proposed diagnostic and rendering strategy
First isolate resolution and layer costs on same physical hardware, same CSS viewport: controlled offscreen backing-pixel scale 1.0/0.75/0.5 relative to current physical resolution, plus explicit native-asset-scale option. Preserve full-resolution textures and models; reduced render-target resolution is visible opt-in experiment, not a silent downgrade of Max. Record exact physical sizes, FPS/p95/p99, CPU/GPU, optical on/off, surface count, actual mode; repeat three runs with 10s warmup and 30s sample for launch. Test browser viewport 1920x1080 at DPR 1 if no sweep yet. Keep viewport and quality/settings constant within comparisons. Compare cold starts to avoid retained contexts. Check browser GPU/compositor trace, display refresh and background throttling. Do not extrapolate 60 FPS from pixel ratios.
Then build bounded pixel-budget renderer: keep static scene precomposed by depth and cached, draw only dynamic vegetation meshes; batch contiguous static runs without altering alpha order; reuse static targets unless invalidated; render low-frequency optical effects into small targets where visual parity holds; merge overlays into shared GPU context incrementally; evaluate local fish targets and atlas/culling after fill-rate proof. Preserve biological simulation, scene composition, roots, loading and controls. Retain Max quality/native mode; explicit selectable render scale with user comparison, no quality downgrade without approval. Three.js/WebGL2 remain candidates after measurements, not immediate fix. P2/Driftwood remain blocked until visual + performance gate. 60 FPS target at agreed device/viewport; report actual results, no guarantee at 8.16 MP on UHD 630.
