# ADR-008 — GPU-native Living Habitat / single scene renderer
Status: proposed, not implemented. 2026-11-25.
## Context and rollback
User reported 0.33.5 approximately doubled FPS but broke the scene; rejected. Exact failure mode not established: no screenshot, browser trace or controlled pixel comparison for this regression. Prior 0.33.4 preserves the previously reported visual experience but was rejected for stuttering. Rollback restores all runtime, assets, configuration and tests from commit 8a4c2eedb606396373d2d237c31c5967330376c2; retain specifications from rejected experiment. 0.33.2 remains the fully accepted static reference. No merge to master.
## Decision proposal
GPU-first retained scene, WebGL on existing stack; no new framework or WebGPU dependency in first spike. React stays UI shell. Avoid full-frame Canvas reconstruction, getImageData, dynamic CPU alpha packing, ImageBitmap transfer and texture re-upload in steady-state GPU path.
- Retain all photographic resources, authored positions, depth planes, grade, crop and camera transforms. Upload textures once; keep static geometry cached. Preserve original photographic alpha, premultiplied-alpha conventions, filtering, color space and lighting. No recoloring, scaling, new assets or changes to fish anatomy/shaders beyond integration.
- Each living plant is a textured strip/mesh anchored at root, with vertex shader displacement matching existing plantOffset curve (species amplitude, phase, height, current, wake). Use a small mesh per instance, static UVs, uniforms for time and wake; validate both zero-deformation and animated poses. CPU integrates local wake scalar for each plant at bounded cadence; render interpolates using elapsed time. Static solids never deform.
- One WebGL context for environment and fish. First spike keeps existing fish material and occlusion contract: generate GPU-only per-plane alpha targets with exactly the same vertex/UV/crop/texture/filter/deformation uniforms as color pass, sample these targets in existing fish fragment path; preserve independent planar depth thresholds and antialias. No CPU readback except explicit diagnostics/tests. Render target format and blending verified with synthetic overlapping translucent sprites. Start with independent alpha textures or packed channels only when proven equivalent. Later evaluate depth-aware sorted compositing with fish per-object depth and correct transparent fin blending; do not assume a normal opaque depth buffer alone solves alpha edges. One shared snapshot per render.
- Preserve existing optical effects and foreground order in spike; use reference comparison before moving them to GPU. Later port water surface, rays, particles and lighting individually using inexpensive shaders/instanced quads. No simultaneous rewrite of fish biology.
- Separate physical proxies from visual alpha. Authored static contour/SDF or capsules per plant/solid, with conservative swept extents and locally deformed proxy parameters for nearby fish. No per-frame full-image collision readback. Keep depth guard and bounded steering; test narrow gaps and no teleport. Collision is not inferred solely from visibility.
- Fallback: keep prior Canvas/Worker renderer selectable and static reference 0.33.2 available; investigate lower-cost pre-baked local pose animation for software with matched alpha, without silently disabling vegetation or reducing quality. Any static/compatibility mode explicitly labelled. Do not exchange whole scene bitmaps across workers in GPU mode.
## Architecture stages
0.33.7A static GPU parity: no movement, same assets/crop/grade/alpha/order/optics/fish; behind default-off flag; deterministic screenshots for desktop/mobile, camera shifts, day/night and observation. GPU target/sampling tests. 0.33.7B one plant with same shader for color/alpha and root/wake; then expand to all plants. 0.33.7C local collision proxies and fallback; validate interactions. 0.33.7D benchmark and stabilize, then consider replacing default. Names are proposed; no stage claimed implemented. Never introduce all changes in a single unvalidated release.
## Quality gates
- Fixed-time deterministic A/B screenshots and pixel-diff plus human review: static pose parity, leaf edges, water gaps, translucent fins, fish in front/behind, no lost colors, order, black canvas, missing objects or flicker. Compare 0.33.2 and 0.33.4; screenshot differences allowed only in explicitly authorized deformation regions. Validate asset loading, context loss, resize, night, reduced motion and scenario transitions. Include synthetic RGBA tests for transparency/color order.
- Profile same machine, browser, viewport, device pixel ratio and quality, 10s warmup + 30s captures, report screen FPS and fish FPS, p50/p95/p99 frame interval, long frames, CPU/GPU timings where available. Proposed goal 60 FPS capable hardware, >=90% baseline 0.33.2, p95 <=20ms and no repeated >50ms. No quality reduction by stealth; no claim of actual gain without measurement.
- No getImageData/texSubImage2D for full dynamic scene masks in GPU steady state; no transfers of whole animated scene; test instrumentation/counters. Verify WebGL1 capabilities/texture units/framebuffer limits; use timer queries only if supported and disjoint false. CPU fallback gets separate performance budget and user-visible label. Failure defaults to original renderer, not black/missing scene.
- Preserve behavior, fish anatomy, controls and biological respiration. No merge until user approves visuals AND performance.
## Future habitat
Living Driftwood remains blocked until both pass. Static authored cavity/portals, physically valid widths, connected paths and emergency breathing egress; one scene renderer can layer front/rear wood and cavity masks. Water Physics, Natural Lighting, Environmental Physics, Cinematic Aquarium unchanged. Do not invent hidden cavity from dark pixels.
